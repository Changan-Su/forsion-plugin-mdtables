# 表格工作台(md-tables)

markdown 表格的行列操作台。光标落进一张表格,表格上方浮出工具条 —— 插入 / 删除 / 上下左右移动行列、
按当前列排序、切换整列对齐。**每个动作是编辑器里的一个事务,Cmd/Ctrl+Z 一步撤销。**

> 宿主编辑器对 markdown 表格此前只给了 Tab 跳格;行列增删、移动、排序、对齐那些按钮全长在 `.db` 多维表上,
> 纯文本表格一个都没有。本插件补的是这一段。

## 功能

| 组 | 做什么 |
|---|---|
| **行** | 上移 / 下移 / 上方插入 / 下方插入 / 删除 |
| **列** | 左移 / 右移 / 左侧插入 / 右侧插入 / 删除 |
| **排序** | 按**光标所在列**升 / 降序。整列都是数字(允许千分位逗号与百分号)按数值排,否则按中文拼音排;空格子永远沉底;相等的行保持原先后 |
| **对齐** | 当前列 左 / 中 / 右 / 默认 |
| **源码** | 产出竖线对齐的 markdown 源码到剪贴板(**中日韩字符按 2 计宽**) |

- 表头行不能删也不能移动;表格至少保留一行数据、一列 —— **到边界会提示,不静默失败**。
- 清单视图(命令面板「表格工作台」):鸟瞰这一篇里的每张表(序号 / 表头预览 / 几列几行),点一行跳过去并展开。
- 新建:笔记里打 `/` 选「插入表格」,输入 `3x4`(行数 x 列数,行数不含表头)。默认尺寸在设置里改。

## ⚠️ 关于「格式化」这个命令,先说清楚它不做什么

**它不改变宿主保存到磁盘时的表格排版。** 落盘形态由宿主的 remark-stringify 独占,每次保存整篇重序列化,
任何手工排版当场被覆盖 —— 插件经 `PmToolkit` 只拿到裸 ProseMirror,拿不到 milkdown ctx,改不了序列化配置。

所以「格式化」的交付面是:**用插件自己的序列化器产出对齐源码(CJK 宽 2 / `\|` 转义 / `<br>` 原样),
放进剪贴板**,给你贴到 GitHub / README / 别的编辑器用。它不写磁盘、不打活文档。

> 顺带一条实测:宿主落盘时**本来就会**对齐竖线(`mdast-util-gfm-table` 默认 `tablePipeAlign`),
> 但 `stringLength` 没配 → 中文按 1 计宽,所以磁盘上的中文表格天然不齐。**这条序列化路径插件改不了。**

## 数据在哪

**哪儿也不在。** 不产出任何文件、不读写笔记库里的其他文件、不联网。
只改你正在编辑的这一篇(经编辑器事务),外加浏览器本地三个界面偏好(工具条开关、新建表格的默认行列数)。

## 范围说明:明确不做什么

1. **不做多维表** —— 宿主内置的 `.db` 是另一套(有类型、有视图、有筛选、有公式)。本插件只管 **markdown 里的纯文本表格**。
2. **不做落盘排版** —— 见上面那节,做不到,不承诺。
3. 不做 CSV 导入导出、不做公式 / 合计、不做单元格合并(GFM 本来就不支持)。
4. **不做全库批量格式化** —— 只管当前编辑器里这一篇。
5. **不抢任何按键** —— 编辑器扩展跑 `normal` 桶,不注册 `handleKeyDown` / `handleTextInput` / `handleDOMEvents.keydown`。
   Tab 在表格里由宿主处理,段落 Tab 是宿主的缩进档,都不碰。

## 已知取舍

- **工具条不是编辑器装饰** —— widget decoration 住在 ProseMirror 的 DOM 子树里,传送不出去,
  画布带 `transform` 时会被平移缩放。所以工具条是插件自己的单例 DOM,挂在最近的 `.am-app` 下,
  靠 `view.coordsAtPos()` 拿视口坐标定位。
- **老式分块笔记(v3)下**,清单视图只提供跳转与复制源码;行列操作请到表格上方的工具条做。
- 贡献点标题(命令面板 / 视图名 / 设置项)是注册时的单字符串,切界面语言后要等重启才跟上;视图内文案实时跟随。

## 兼容

`apiVersion 1`。旧宿主缺 `registerEditorExtension` 时工具条与行列操作静默不挂,清单视图与命令仍在。
